# Editing your website text

Edit `dist/index.html` for the homepage. It now has section markers, indented elements, and paragraphs wrapped onto short lines. Line breaks in the source do not create extra paragraphs on the website.

## Change text

Edit the words between `<p>` and `</p>` for a paragraph, or between `<h3>` and `</h3>` for a heading. Keep the surrounding tags, section IDs, and class names intact.

```html
<p>
  Your paragraph goes here. You can split it across several lines
  to make it easier to read while editing.
</p>
```

For a new paragraph, copy an entire `<p>...</p>` block. For a new teaching entry, copy one entire `<article class="entry">...</article>` block, then change the year, heading, and description.

For links, edit the destination inside `href="..."` and the visible words between `<a>` and `</a>`. Write an ampersand as `&amp;` in HTML text.

The online CV is in `dist/cv.html`; its downloadable Word file is separate. The snow map's generated labels are in `dist/snow.js`. Daily snow images and metadata are generated by workflows.

## Save and publish

1. In GitHub Desktop, fetch and pull any remote changes before you start editing. The daily snow workflow can add commits automatically.
2. Edit and save `dist/index.html`. Preview it in your browser to check your text (the snow map requires a local web server; opening the file directly still shows the text).
3. Commit your edits in GitHub Desktop, then click **Push origin**. If remote changes arrived while you were editing, pull and merge them first.
4. Wait for the Pages deployment, then refresh the site. Stylesheet and script URLs are automatically versioned on deployment.

`.editorconfig` supplies consistent indentation in editors that support it. Avoid minifying the HTML: the readable source is the version we maintain.
